# Plan 01-02: Modular Chatbot Adapters for ChatGPT, Claude & Gemini

## Goal
Implement robust, resilient content script adapters for ChatGPT, Claude, and Gemini that detect generation lifecycle events without reading user prompt text or model response contents.

## Context
Each AI chatbot platform exhibits distinct DOM lifecycles and event mechanics:
- **ChatGPT**: Uses `data-composer-markdown`, capture-phase Enter listeners (since the host's own Enter handler runs on the same node), and virtualizes long chats (requiring stable turn IDs rather than node index counts).
- **Claude**: Uses Tiptap editor and runs asynchronous conversation hydration on chat switch, requiring a settlement debounce window so history playback is not mistaken for a new prompt submission.
- **Gemini**: Built with Angular Web Components (`rich-textarea`, `user-query`, `pending-request`), tearing down transient streams into permanent `model-response` turns upon completion.

## Tasks

<task id="1">
<title>Implement ChatGPT Adapter</title>
<action>
Create `apps/extension/entrypoints/content/adapters/chatgpt.ts`:
1. Selectors:
   - Composer: `#prompt-textarea, [data-mobile-composer-prompt], [data-composer-markdown]`.
   - Send Button: `[data-testid="send-button"], button[data-composer-submit], form button[type="submit"][aria-label="Send"]`.
   - Stop Button: `button[aria-label="Stop"], button[data-testid="stop-button"]`.
   - User Message: `[data-message-author-role="user"], [data-user-message-bubble]`.
2. Lifecycle handling:
   - Attach capture-phase `click` listener to send button and `keydown` listener to composer (Enter without Shift).
   - Snapshot trailing message ID (`data-message-id` or ancestor `li[id]`).
   - Monitor `MutationObserver` for new user message node; invoke `onAnchorReady` escaping bubble container.
   - Maintain `watchForReanchor` during dynamic chat stream rebuilds.
   - Signal `onDone` when Stop button is observed and then disappears, or Send button returns.
</action>

</verify>
</task>

<task id="2">
<title>Implement Claude Adapter</title>
<action>
Create `apps/extension/entrypoints/content/adapters/claude.ts`:
1. Selectors:
   - Composer: `[data-testid="chat-input"]`.
   - Send Button: `button[aria-label="Send message"]`.
   - User Message: `[data-testid="user-message"]`.
   - User Bubble Containers: `[data-cds="UserMessage"], [data-user-message-bubble]`.
2. Lifecycle handling:
   - Escape bubble styling: `resolveAnchor` searches upward for container element escaping the rounded gray bubble into the full-width row.
   - Implement `settling` window: When loading an existing chat or navigating threads, debounce DOM mutations until quiescent (300ms) to prevent old messages from triggering ads.
   - Track submission timestamps to corroborate user interaction with DOM appends (`SUBMIT_CORROBORATION_MS = 1000`).
   - Detect completion when the composer state shifts from generating/disabled back to enabled.
</action>
<verify>
Verify `ClaudeAdapter` compiles cleanly and implements `PromptAdapter` contract.
</verify>
</task>

<task id="3">
<title>Implement Gemini Adapter</title>
<action>
Create `apps/extension/entrypoints/content/adapters/gemini.ts`:
1. Selectors:
   - Composer: `rich-textarea [contenteditable]`.
   - Send Button: `button[aria-label="Send message"]`.
   - User Query: `user-query`.
   - Model Response: `model-response`.
2. Lifecycle handling:
   - Capture submit via capture-phase Enter keydown and send button click.
   - Detect transient turn wrapper (`<pending-request>`); immediately anchor ad card after `user-query`.
   - When Gemini replaces the transient container with permanent `model-response`, re-anchor the active card node onto the new permanent turn container.
   - Signal `onDone` when generation indicators subside.
</action>
<verify>
Verify `GeminiAdapter` compiles cleanly and implements `PromptAdapter` contract.
</verify>
</task>
